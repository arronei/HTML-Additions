Abstract

This specification extends HTML with a link content attribute for text-entry input elements and for select elements. The attribute names the control that continues the current one. The user agent moves focus through the resulting chain of controls as each one fills up, and carries typing, deletion, caret movement, pasting, and autofill across the controls. When linked controls share a name, their values are submitted together as one form entry. Segmented fields such as telephone numbers and one-time codes then work without script.

1. Introduction

This section is non-normative.

Many forms collect a single value through several small text fields: a telephone number split into area code, central office code, and line number; a six-digit verification code with one box per digit; a card number in groups of four. Every one of these forms currently needs script to:

  • move focus to the next field once the current one is full;

  • move back to the previous field when the user presses Backspace at the start of a field;

  • let the arrow keys move the caret from one field into the next;

  • spread pasted or autofilled text across the fields instead of cutting it off at the first field’s maxlength; and

  • put the pieces back together for the server, usually by copying them into a hidden field.

These scripts are rewritten for countless sites, behave slightly differently on each one, and often break input methods, autofill, and assistive technology.

The link attribute lets authors declare the relationship instead, and leaves the behavior to the user agent.

A form asks for a North American telephone number in three parts: 
<form action="/register">
  <fieldset>
    <legend>Phone number</legend>
    <input type="tel" id="areaCode" name="phoneNumber" maxlength="3"
           link="centralOfficeCode" autocomplete="tel-area-code" aria-label="Area code">
    <input type="tel" id="centralOfficeCode" name="phoneNumber" maxlength="3"
           link="lineNumber" autocomplete="tel-local-prefix" aria-label="Central office code">
    <input type="tel" id="lineNumber" name="phoneNumber" maxlength="4"
           autocomplete="tel-local-suffix" aria-label="Line number">
  </fieldset>
  <button>Register</button>
</form>

The user types 5551234567 into the first field. After the third digit, focus moves to centralOfficeCode; after the sixth, it moves to lineNumber. Submitting the form sends one entry:

phoneNumber=5551234567

Without the link attributes, the same form would send three entries: phoneNumber=555&phoneNumber=123&phoneNumber=4567.

Two attributes do two separate jobs:

  • link decides where focus and text go next.

  • name decides what is submitted together: linked controls that share a name are submitted as one entry, with values concatenated in link order.

User agents that don’t support this specification still show separate, working fields, and submit each field as its own entry.

2. The link attribute

2.1. Linkable elements

A linkable element is either:

  • an input element whose type attribute is in the Text, Search, Telephone, or Password state; or

  • a select element that does not have a multiple attribute.

Note: Controls that aren’t used to enter a piece of a larger value, such as checkboxes and radio buttons, are not linkable. select elements with a multiple attribute are excluded because they can contribute more than one value.

2.2. The content attribute

The link content attribute identifies the control that comes next in a sequence of controls that together hold a single value. It can be specified on input and select elements.

If present, the attribute’s value must be the ID of a linkable element in the same tree as the element, other than the element itself. The attribute must only be specified on linkable elements. On any other input or select element, the attribute does not apply and has no effect.

Authors must not specify link attributes such that two elements have the same link target, or such that following link targets from an element eventually leads back to that element.

2.3. The IDL attribute

interface mixin LinkedControlAttributes {
  [CEReactions, Reflect="link"] attribute Element? linkElement;
};
HTMLInputElement includes LinkedControlAttributes;
HTMLSelectElement includes LinkedControlAttributes;

The linkElement IDL attribute must reflect the link content attribute.

Note: Like commandForElement, linkElement returns the element that the attribute refers to, and can be set to an element that has no ID. Setting it sets the content attribute to the empty string.

const [area, prefix, line] = form.querySelectorAll('input[name="phoneNumber"]');

// Build the chain from script. None of these elements need an id.
area.linkElement = prefix;
prefix.linkElement = line;

area.linkElement === prefix;               // true
new FormData(form).get("phoneNumber");     // e.g. "5551234567"

// Feature detection.
const supported = "linkElement" in HTMLInputElement.prototype;

2.4. Link targets and link chains

The link target of an element element is the result of these steps:

  1. If element is not a linkable element, then return null.

  2. Let target be the result of running element’s get the link-associated element.

  3. If any of the following are true, then return null:

    • target is null;

    • target is element;

    • target is not a linkable element; or

    • target’s root is not element’s root.

  4. Return target.

The link source of an element element is the first linkable element, in tree order, among the inclusive descendants of element’s root, whose link target is element. If there is no such element, the link source is null.

Note: When more than one element names the same link target, only the first of them in tree order is linked to it. The others act as if they had no link attribute.

The tentative next control of an element element is element’s link target, if that is not null and its link source is element. Otherwise, it is null.

An element element is in a link cycle if, starting with current set to element’s tentative next control and then repeatedly setting current to current’s tentative next control, current eventually becomes element.

Note: An element is the tentative next control of at most one other element, so this process always either comes back to element or reaches null.

The next linked control of an element element is null if element is in a link cycle, and element’s tentative next control otherwise.

The previous linked control of an element element is null if element is in a link cycle, and element’s link source otherwise.

Note: Controls that form a cycle aren’t linked at all. That way, an authoring mistake gives separate, ordinary controls instead of a chain with no clear start.

The link chain of a linkable element element is the list returned by these steps:

  1. Let head be element.

  2. While head’s previous linked control is not null, set head to head’s previous linked control.

  3. Let chain be « head ».

  4. Let current be head’s next linked control.

  5. While current is not null:

    1. Append current to chain.

    2. Set current to current’s next linked control.

  6. Return chain.

A linked control is a linkable element whose link chain’s size is greater than 1. A linked text control is a linked control that is an input element.

A linked control control is available if control is focusable and, if control is an input element, control is mutable.

The next available linked control of a linked control control is the result of these steps:

  1. Let current be control’s next linked control.

  2. While current is not null and current is not available, set current to current’s next linked control.

  3. Return current.

The previous available linked control of a linked control is found the same way, using previous linked controls instead of next linked controls.

Note: Skipping controls that aren’t available means a disabled, read-only, or hidden piece of a value, such as a fixed country code, doesn’t stop the user from moving through the rest.

The following markup is non-conforming. User agents handle it as described in the comments. 
<!-- A cycle: neither control is linked. -->
<input id="a" link="b" maxlength="2">
<input id="b" link="a" maxlength="2">

<!-- Two controls link to "z". Only "p", the first in tree order, is linked to it. -->
<input id="p" link="z" maxlength="3">
<input id="q" link="z" maxlength="3">
<input id="z" maxlength="3">

<!-- <textarea> is not a linkable element, so the link attribute is ignored. -->
<input link="notes" maxlength="10">
<textarea id="notes"></textarea>

3. User interaction

The requirements in this section make a link chain behave, for editing, like one field divided into segments. They apply only to actions the user takes, not to changes made by script (for example, setting value or calling setSelectionRange()).

3.1. Advancing focus

To advance focus from a linked control control:

  1. If the user has turned off automatic focus advancement (see § 6 Accessibility considerations), then return.

  2. Let next be control’s next available linked control.

  3. If next is null, then return.

  4. Run the focusing steps for next.

  5. If next is an input element and is focused, then set the selection range of next with 0 and the length of next’s value.

Note: Selecting the next control’s contents means typing replaces whatever it already holds, as it does when the user tabs into a text field on most platforms.

To check for automatic advance for a linked text control control:

  1. If control is not focused, then return.

  2. If control has no maximum allowed value length, then return.

  3. If the length of control’s value is less than control’s maximum allowed value length, then return.

  4. If control’s selection is not collapsed, or the text entry cursor position is not at the end of control’s value, then return.

  5. Advance focus from control.

Whenever the user agent queues a task to fire an input event at a linked text control control because the user inserted text into it, it must then queue an element task on the user interaction task source given control to check for automatic advance for control. Inserting text includes typing, committing an input method composition, pasting, dropping, and accepting a replacement suggestion, such as a spelling correction. It does not include autofill, updates to an input method composition that is still in progress, or deleting text.

Note: The check runs after the input event has been dispatched. If an event listener changes the control’s value or moves focus, the check sees the result.

When the user picks an option of a linked control control that is a select element from the element’s drop-down box, the user agent must, after the task queued by send select update notifications has run, queue an element task on the user interaction task source given control to run these steps:

  1. If control is not focused, then return.

  2. Advance focus from control.

The user agent must not advance focus from a select element when the user changes its selected option without picking it from the drop-down box. This covers using the arrow keys while the drop-down box is closed, as some platforms allow, and a select element that is being rendered as a list box.

3.2. Distributing text

When the user inserts text into a linked text control control, and the insertion was not canceled (for example, by canceling its beforeinput event [UIEVENTS]), the user agent must run distribute text given control, the inserted text, and the start and end offsets of the part of control’s value that the insertion replaces. The inserted text is taken after the processing the user agent normally applies to text inserted into control, such as removing line breaks. The replaced part is the selection, or an empty range at the text entry cursor position if the selection is collapsed. If distribute text returns false, the user agent must insert the text as it normally would. Otherwise, the insertion has been fully handled.

When the user agent autofills a linked text control control with a string that is longer than control’s maximum allowed value length, it must run distribute text given control, the string, 0, the length of control’s value, and false, instead of truncating the string.

To distribute text given a linked text control control, a string text, integers start and end, and an optional boolean move focus (default true):

  1. If control has no maximum allowed value length, then return false.

  2. Let value be control’s value.

  3. Let before be the code unit substring from 0 to start within value.

  4. Let after be the code unit substring from end to value’s length within value.

  5. If the sum of the lengths of before, text, and after is less than or equal to control’s maximum allowed value length, then return false.

  6. Let target be control.

  7. Let prefix be before, let suffix be after, and let remaining be text.

  8. Let changed be an empty list.

  9. Let last target be control, and let caret be the length of before.

  10. While true:

    1. Let room be target’s maximum allowed value length minus the length of prefix, or the length of remaining if target has no maximum allowed value length. If room is less than 0, set room to 0.

    2. Let piece be the code unit prefix of remaining whose length is the smaller of room and the length of remaining. If piece ends with a leading surrogate and remaining is longer than piece, remove that last code unit from piece.

    3. Set remaining to the code unit substring from the length of piece to the length of remaining within remaining.

    4. Let excess be the sum of the lengths of prefix, piece, and suffix, minus target’s maximum allowed value length. If target has no maximum allowed value length, or excess is less than 0, set excess to 0.

    5. Let kept be the code unit substring from the smaller of excess and the length of suffix, to the length of suffix, within suffix. If kept starts with a trailing surrogate, remove that first code unit from kept.

    6. Let new value be the concatenation of « prefix, piece, kept ».

    7. If new value is not identical to target’s value, then:

      1. Set target’s value to new value, and set its dirty value flag to true. The value counts as having last been changed by a user edit.

      2. Append target to changed.

    8. Set last target to target, and set caret to the sum of the lengths of prefix and piece.

    9. If remaining is the empty string, then break.

    10. Let next be target’s next available linked control.

    11. If any of the following are true, then break:

      • next is null;

      • next is not an input element; or

      • the type attribute of exactly one of target and next is in the Password state.

    12. Set target to next, set prefix to the empty string, and set suffix to next’s value.

  11. If move focus is true, then:

    1. If last target is not control, then run the focusing steps for last target.

    2. If last target is focused, then set the selection range of last target with caret and caret.

  12. For each changed control of changed, queue an element task on the user interaction task source given changed control to run these steps:

    1. Fire an event named input at changed control, with the bubbles and composed attributes initialized to true.

    2. If move focus is false, or changed control is neither control nor last target, then set changed control’s user validity to true and fire an event named change at changed control, with the bubbles attribute initialized to true.

  13. Return true.

Note: Text that fits is inserted normally. When text doesn’t fit, each control takes as much as it can hold after the insertion point. To make room, it replaces only as many of the following characters as it has to. Anything left over is inserted at the start of the next available linked text control, under the same rule. This one rule covers pasting a whole value into the first control, typing past the end of a full control into the next one, and typing over a full chain. Distribution stops at a select element, at the end of the chain, and at any boundary between a Password control and a control of another type. Text left over at that point is discarded, as it would be by maxlength.

Note: The input events fire in link order, after focus has moved. The control that ends up focused, and the control the user started in, get their change events in the usual way, when they lose focus. Controls in between, which never have focus, get their change events straight away, as does every control changed by autofill.

With the telephone number fields from the introduction:
User action areaCode centralOfficeCode lineNumber Focus afterward
Type 555 into the empty areaCode 555 centralOfficeCode, contents selected
Type 123 555 123 lineNumber
Press Backspace in the empty lineNumber 555 12 centralOfficeCode, caret at end
Click at the end of areaCode and type 9 555 912 centralOfficeCode, caret after 9
Type 8 555 982 centralOfficeCode, caret after 8
Select all of areaCode and paste 5551234567 555 123 4567 lineNumber, caret at end
Paste 8005550199 with the caret at the start of areaCode 800 555 0199 lineNumber, caret at end

3.3. Moving between linked text controls

When the user asks to delete the content just before the text entry cursor position (for example, by pressing Backspace) in a linked text control control whose selection is collapsed at the start of its value, and the request was not canceled, the user agent must run these steps instead of its usual behavior:

  1. Let previous be control’s previous available linked control.

  2. If previous is null, then return.

  3. Run the focusing steps for previous.

  4. If previous is an input element and is focused, then:

    1. Let length be the length of previous’s value.

    2. Set the selection range of previous with length and length.

    3. Carry out the user’s deletion request in previous, as if the user had made it there. This includes firing the events such a deletion fires, and deleting as much text as the platform’s conventions say (for example, one grapheme cluster).

When the user asks to move the text entry cursor position back by one position, without extending the selection, in a linked text control control whose selection is collapsed at the start of its value, and the request was not canceled, the user agent must run these steps instead of its usual behavior. An example of such a request is the ← key in a left-to-right control.

  1. Let previous be control’s previous available linked control.

  2. If previous is null or is not an input element, then return and act as usual.

  3. Run the focusing steps for previous.

  4. If previous is focused, then set the selection range of previous with length and length, where length is the length of previous’s value.

When the user asks to move the text entry cursor position forward by one position, without extending the selection, in a linked text control control whose selection is collapsed at the end of its value, and the request was not canceled, the user agent must run these steps instead of its usual behavior. An example of such a request is the → key in a left-to-right control.

  1. Let next be control’s next available linked control.

  2. If next is null or is not an input element, then return and act as usual.

  3. Run the focusing steps for next.

  4. If next is focused, then set the selection range of next with 0 and 0.

Note: The arrow keys never move focus into or out of a select element, because they already change the selected option there. Backspace can move focus back to a select element, but it doesn’t change the selection.

Note: The keydown event for these keys fires at the control where the user pressed the key, before focus moves. Canceling it stops the behavior.

4. Form submission

4.1. Joined groups

The joined group of a linked control control is the list of the items member of control’s link chain, in order, for which all of the following are true:

  • member has a name attribute whose value is identical to the value of control’s name attribute;

  • member’s form owner is not null and is control’s form owner;

  • member is not disabled; and

  • member does not have a datalist element ancestor.

The joined value of a joined group group is the result of these steps:

  1. Let value be the empty string.

  2. For each member of group:

    1. If member is a select element, then, for each option element option in member’s list of options whose selectedness is true and that is not disabled, append option’s value to value.

    2. Otherwise, append member’s value to value.

  3. Return value.

Note: Only controls that are linked and share a name are joined. Controls that share a name without being linked, such as a group of checkboxes, still submit separate entries. Linked controls with different names still move focus from one to the next, but each name gets its own entry. A disabled member contributes nothing, but doesn’t split the group.

4.2. Changes to constructing the entry list

The algorithm to construct the entry list [HTML] is changed as follows. Inserted text is marked like this and removed text is marked like this . Steps that don’t change are summarized in brackets.

  1. For each element field in controls, in tree order:

    1. [If any of the skip conditions are true, such as field being disabled, then continue.]

    2. [If field is an Image Button, then append its coordinates and continue.]

    3. [If field is a form-associated custom element, then perform its entry construction algorithm and continue.]

    4. If either the field element does not have a name attribute specified, or its name attribute’s value is the empty string, then continue.

    5. Let name be the value of the field element’s name attribute.

    6. If field is a linked control and the size of field’s joined group is greater than 1, then:
      1. If field is not the first item of field’s joined group, then continue.
      2. Create an entry with name and the joined value of field’s joined group, and append it to entry list.
    7. If Otherwise, if the field element is a select element, then for each option element in the select element’s list of options whose selectedness is true and that is not disabled, create an entry with name and the value of the option element, and append it to entry list.

    8. [The remaining "Otherwise, if" steps for checkboxes, radio buttons, file uploads, _charset_, and all other controls are unchanged.]

    9. [If the element has a dirname attribute, then append its directionality entry. This step is unchanged.]

Note: The joined entry is appended when the loop reaches the group’s first member in link order. Members that come later in the group are skipped, wherever they are in the tree. The dirname step still runs for the first member, so a joined group contributes at most one dirname entry.

Note: FormData’s constructor and the formdata event use the same algorithm. Scripts calling new FormData(form) therefore see the joined value, exactly as the server does.

4.3. Interaction with other features

This section is non-normative.

Constraint validation

Each control is validated on its own. Authors can use required, minlength, and pattern on each segment, for example pattern="[0-9]{3}".

form.elements

This specification doesn’t change elements or RadioNodeList. Each segment remains its own control, and form.elements.phoneNumber is a RadioNodeList of all three fields.

Autofill

Existing autofill field names already describe common segments: tel-area-code, tel-local-prefix, and tel-local-suffix for telephone numbers. When a user agent fills a whole value into the first segment, such as a one-time-code, § 3.2 Distributing text spreads it across the chain.

User agents without support

Each segment is submitted as its own entry with the shared name, for example phoneNumber=555&phoneNumber=123&phoneNumber=4567. A server that joins repeated values for such names accepts submissions from both kinds of user agent.

5. Changes to the HTML Standard

To integrate this specification into the HTML Standard [HTML], make these changes:

  1. In the input element:

    • Add link to the element’s content attributes.

    • Add HTMLInputElement includes LinkedControlAttributes; to the DOM interface.

    • Add a link row to the table that summarizes which content attributes apply to each type state. Mark it "Yes" for the Text, Search, Telephone, and Password states, and not applicable for every other state.

    • In the "Bookkeeping details" of the Text and Search, Telephone, and Password states, add link to the attributes that apply, and linkElement to the IDL attributes that apply. In every other state, add link to the content attributes that must not be specified.

  2. In the select element, add link to the element’s content attributes, and HTMLSelectElement includes LinkedControlAttributes; to the DOM interface.

  3. Apply the change in § 4.2 Changes to constructing the entry list.

  4. Add the definitions in § 2 The link attribute, § 3 User interaction, and § 4.1 Joined groups as a new subsection of "Attributes common to form controls".

  5. In the index of element attributes, add a row: attribute link; elements input, select; description "Next control in a sequence of linked controls"; value "ID".

6. Accessibility considerations

Moving focus while the user is typing is a change of context under Success Criterion 3.2.2 On Input [WCAG22], unless the user is told about the behavior before using the controls. Some users, including many screen reader and screen magnifier users, find automatic focus movement disorienting.

  • User agents should give users a way to turn off automatic focus advancement. When it is off, advance focus does nothing. Users can still move between controls by typing past the end of a full control (§ 3.2 Distributing text), with the arrow keys and Backspace (§ 3.3 Moving between linked text controls), or with sequential focus navigation.

  • Authors should group linked controls, for example with a fieldset and legend. They should give each control its own accessible name, and say in the group’s label or nearby instructions that focus moves automatically.

  • User agents should expose link chains to accessibility APIs, so that assistive technology can tell users where a control sits in its chain (for example, "area code, 1 of 3").

Define how link chains map to platform accessibility APIs in [HTML-AAM-1.0]. One option is a "flows to" relationship, as for aria-flowto [WAI-ARIA-1.2], together with the position in the chain and the chain’s size.

Because distribution keeps pasting and autofill working, users of voice control, switch access, and password managers can supply a whole value at once instead of entering it one segment at a time.

7. Security and privacy considerations

  • This specification exposes no new information. A joined entry contains exactly the values that its controls would otherwise submit separately.

  • A link target must be in the same tree as the element that names it. Links therefore can’t move focus or text into another document, such as a cross-origin iframe, or across a shadow root boundary.

  • Focus moves only in response to the user’s own editing actions, and only within one document. Script can already move focus with focus().

  • Distribute text stops at any boundary between a Password control and a control of another type. Pasted secrets therefore never spill from a masked field into a visible one, or the other way around.

8. More examples

This section is non-normative.

A select element can be part of a chain. When the user picks a country code, focus moves to the area code, and the joined value comes out in a full international format. 
<fieldset>
  <legend>Mobile number (focus moves to the next box automatically)</legend>
  <select name="mobile" link="mobileArea" autocomplete="tel-country-code"
          aria-label="Country code">
    <option value="+1">+1</option>
    <option value="+52">+52</option>
  </select>
  <input type="tel" id="mobileArea" name="mobile" maxlength="3" link="mobilePrefix"
         autocomplete="tel-area-code" aria-label="Area code">
  <input type="tel" id="mobilePrefix" name="mobile" maxlength="3" link="mobileLine"
         autocomplete="tel-local-prefix" aria-label="Prefix">
  <input type="tel" id="mobileLine" name="mobile" maxlength="4"
         autocomplete="tel-local-suffix" aria-label="Line number">
</fieldset>

The form submits mobile=%2B15551234567, which is +15551234567 once percent-decoded.

A one-time code with one box per digit. Pasting 482913 into the first box, or autofilling it there, fills all six boxes. 
<form action="/verify" method="post">
  <fieldset>
    <legend>Enter the 6-digit code we sent you</legend>
    <input name="code" id="d1" link="d2" maxlength="1" inputmode="numeric"
           autocomplete="one-time-code" aria-label="Digit 1">
    <input name="code" id="d2" link="d3" maxlength="1" inputmode="numeric" aria-label="Digit 2">
    <input name="code" id="d3" link="d4" maxlength="1" inputmode="numeric" aria-label="Digit 3">
    <input name="code" id="d4" link="d5" maxlength="1" inputmode="numeric" aria-label="Digit 4">
    <input name="code" id="d5" link="d6" maxlength="1" inputmode="numeric" aria-label="Digit 5">
    <input name="code" id="d6" maxlength="1" inputmode="numeric" aria-label="Digit 6">
  </fieldset>
  <button>Verify</button>
</form>

The form submits code=482913. If the user notices a wrong digit, they can press Backspace repeatedly to move back through the boxes, or select a digit and type a new one.

Links and names do different jobs. The last card number group links to the expiry month so focus keeps moving, but the card number and the expiry date have different names, so each is its own entry. 
<input name="cc-number" id="cc1" link="cc2" maxlength="4" inputmode="numeric"
       autocomplete="cc-number" aria-label="Card number, group 1 of 4">
<input name="cc-number" id="cc2" link="cc3" maxlength="4" inputmode="numeric"
       aria-label="Card number, group 2 of 4">
<input name="cc-number" id="cc3" link="cc4" maxlength="4" inputmode="numeric"
       aria-label="Card number, group 3 of 4">
<input name="cc-number" id="cc4" link="ccMonth" maxlength="4" inputmode="numeric"
       aria-label="Card number, group 4 of 4">
<select name="cc-exp" id="ccMonth" link="ccYear" autocomplete="cc-exp-month"
        aria-label="Expiry month">
  <option value="01">01</option> <!-- … --> <option value="12">12</option>
</select>
<select name="cc-exp" id="ccYear" autocomplete="cc-exp-year" aria-label="Expiry year">
  <option value="26">2026</option> <!-- … --> <option value="35">2035</option>
</select>

Choosing 12 and 2030 submits cc-number=4111111111111111&cc-exp=1230. Pasting a 16-digit card number into the first group fills all four groups. Distribution stops at the select element.

9. Open issues

Attribute name. link is easy to confuse with the link element and with the obsolete link attribute of body. Alternatives include next, linkto, and continues.

Formatting characters in pasted text. Pasting (555) 123-4567 into the telephone fields spreads the parentheses, space, and hyphen across the segments. Should user agents drop such characters when every control in the chain has inputmode="numeric", or should authors signal the allowed characters some other way?

Separator. Should authors be able to put a separator between the joined values, for example with a joiner="-" attribute on the first control?

More controls. Should textarea, input elements in the Number, Email, and URL states, or select elements with multiple be linkable?

More editing commands. Should Delete at the end of a control, word deletion, and Home/End also cross control boundaries?

Validating the whole value. Should there be a way to validate the joined value as a whole, for example a pattern that applies to the entire chain?

Conformance

Conformance requirements are expressed with a combination of descriptive assertions and RFC 2119 terminology. The key words “MUST”, “MUST NOT”, “REQUIRED”, “SHALL”, “SHALL NOT”, “SHOULD”, “SHOULD NOT”, “RECOMMENDED”, “MAY”, and “OPTIONAL” in the normative parts of this document are to be interpreted as described in RFC 2119. However, for readability, these words do not appear in all uppercase letters in this specification.

All of the text of this specification is normative except sections explicitly marked as non-normative, examples, and notes. [RFC2119]

Examples in this specification are introduced with the words “for example” or are set apart from the normative text with class="example", like this:

This is an example of an informative example.

Informative notes begin with the word “Note” and are set apart from the normative text with class="note", like this:

Note, this is an informative note.
